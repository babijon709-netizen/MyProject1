# Укрепление сборки: возможности и границы

Реализованы две дополнительные проверки:

1. Каждый `POST /auth` содержит свежий 128-битный nonce из `/dev/urandom`. Worker возвращает `enabled:<тот же nonce>` только для разрешённого, незабаненного устройства. Бинарь проверяет точное совпадение nonce, HTTPS и HTTP 200; старый записанный ответ `enabled` нельзя просто воспроизвести. При запуске без связи доступ не выдаётся после трёх коротких попыток. Во время работы один сетевой сбой не завершает процесс; после 180 секунд без успешного подтверждения он останавливается. Явный ответ сервера `disabled`/бан завершает работу при ближайшей проверке.
2. `build.sh` записывает SHA-256 исполняемых файлов `benzware` и `benzhack_dump` в распространяемый `benzware.sh`. Оболочка проверяет распакованные файлы **перед запуском**. На Android должен быть доступен `sha256sum` (при необходимости: `pkg install coreutils` в Termux и корректный PATH у root).

Эти меры **не** обеспечивают неподделываемость. Владелец root-устройства может изменить саму оболочку и встроенный хеш, извлечь файл и запустить его напрямую, заменить `curl`/`sha256sum` или удалить проверку nonce в бинаре. Ни клиентская проверка собственной целостности, ни секрет внутри клиентского файла не могут доказать удалённому серверу, что исполняемый код не менялся. Блокировки по HWID также работают только с клиентом, который добровольно выполняет проверки.

Для настоящего контроля над критически необходимой функцией её нельзя полностью отдавать клиенту. В этом проекте чтение и изменение памяти игры происходят на телефоне; Worker не может выполнять эти действия вместо телефона. Поэтому обещать остановку **любого** изменённого бинаря было бы неверно.

## Порядок обновления

1. Опубликуйте **новый** код `cloudflare/worker.mjs` на **том же** Worker. Binding D1 `CONTROL_DB`, таблицы и секреты бота должны остаться настроены. Старый клиент после публикации больше не пройдёт `/auth`, потому что его ответ не содержит nonce (это намеренный отказ). Не обновляйте Worker, пока не готовы распространить новую сборку.
2. Скачайте новый артефакт `benzware-sh-arm64-v8a`, распакуйте и замените старый `benzware.sh` на устройстве. Завершите старый процесс и запустите новый. Если `sha256sum` не найден, установите Termux `coreutils` и убедитесь, что root наследует путь `/data/data/com.termux/files/usr/bin`.
3. Проверьте `/status` и запуск. Сообщения `server denied access` и `authorization unavailable` имеют разные причины: первое — явный отказ `/auth` (общий OFF, бан, старый Worker); второе — недоступность сети/Worker/D1, таймаут или квота. `device ID unavailable` и `curl not found` указывают на проблемы конкретного телефона. При включённом общем переключателе проверьте устройство через `/devices` в боте.

**Важно:** HTTP `/status` остался публичным индикатором общего выключателя, но новый бинарь отправляет `POST /auth` с HWID и nonce. По одному `/status` нельзя судить о персональном бане или успешной проверке nonce.
