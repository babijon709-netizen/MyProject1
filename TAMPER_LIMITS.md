# Укрепление сборки: возможности и границы

Реализованы две дополнительные проверки:

1. Каждый `POST /auth` содержит свежий 128-битный nonce из `/dev/urandom`. Worker возвращает `enabled:<тот же nonce>` только для разрешённого, незабаненного устройства. Бинарь проверяет точное совпадение nonce, HTTPS и HTTP 200; старый записанный ответ `enabled` нельзя просто воспроизвести. При запуске без связи доступ не выдаётся после трёх коротких попыток. Во время работы один сетевой сбой не завершает процесс; после 300 секунд (5 минут) без успешного подтверждения он останавливается. Если соединение недоступно намеренно, выключение может задержаться на это время; fail-closed при запуске сохраняется. Только точный ответ сервера `disabled`/бан завершает работу при ближайшей проверке; неправильный nonce или посторонняя страница HTTP 200 не разрешают работу и не сбрасывают отсчёт, но во время запущенной сессии считаются временным сбоем до истечения срока.
2. `build.sh` записывает SHA-256 исполняемых файлов `benzware` и `benzhack_dump` в распространяемый `benzware.sh`. Оболочка проверяет распакованные файлы **перед запуском**. На стандартном Android используется системный `sha256sum` либо `/system/bin/toybox sha256sum`; установки Termux не требуется.

Эти меры **не** обеспечивают неподделываемость. Владелец root-устройства может изменить саму оболочку и встроенный хеш, извлечь файл и запустить его напрямую, изменить хранилище CA или `sha256sum` или удалить проверку nonce в бинаре. Ни клиентская проверка собственной целостности, ни секрет внутри клиентского файла не могут доказать удалённому серверу, что исполняемый код не менялся. Блокировки по HWID также работают только с клиентом, который добровольно выполняет проверки.

Для настоящего контроля над критически необходимой функцией её нельзя полностью отдавать клиенту. В этом проекте чтение и изменение памяти игры происходят на телефоне; Worker не может выполнять эти действия вместо телефона. Поэтому обещать остановку **любого** изменённого бинаря было бы неверно.

## Порядок обновления

1. Если ваш Worker уже поддерживает `/auth` с nonce, обновлять его для встроенного TLS не нужно: меняется только Android-бинарь. Если Worker ещё старый, опубликуйте код `cloudflare/worker.mjs` на **том же** Worker, сохранив D1 binding `CONTROL_DB`, таблицы и секреты бота.
2. Скачайте новый артефакт `benzware-sh-arm64-v8a`, распакуйте и замените старый `benzware.sh` на устройстве. Завершите старый процесс и запустите новый. Системный Android должен иметь `sha256sum` либо `/system/bin/toybox sha256sum`; дополнительное ПО на каждом телефоне не нужно.
3. Проверьте `/status` и запуск. Сообщения `server denied access` и `authorization unavailable` имеют разные причины: первое — явный отказ `/auth` (общий OFF, бан, старый Worker); второе — недоступность сети/Worker/D1, таймаут или квота. `device ID unavailable` указывает на проблему идентификатора конкретного телефона. `curl not found` означает, что на нём по-прежнему запущен старый файл, а не эта сборка. При включённом общем переключателе проверьте устройство через `/devices` в боте.

**Важно:** HTTP `/status` остался публичным индикатором общего выключателя, но новый бинарь отправляет `POST /auth` с HWID и nonce. По одному `/status` нельзя судить о персональном бане или успешной проверке nonce.
