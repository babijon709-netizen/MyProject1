# Управление benzware через Telegram-бота

Этот способ работает на **том же бесплатном Cloudflare Worker**, который уже используется для `/status`. Отдельный сервер и платный хостинг не нужны. Бот **не запускает** бинарь на телефоне и не обновляет его: он меняет состояние через Worker (в KV до миграции, в D1 после миграции). Сам бинарь читает `/status` перед запуском и примерно раз в 10 секунд после него в новой сборке.

Команды в **личном чате** с ботом: `/on` (включить), `/off` (выключить), `/status` (показать состояние), `/help` (подсказка). Управлять может только один Telegram-аккаунт с указанным числовым ID. Группы и посторонние игнорируются.

## Что понадобится

- Уже созданные по [основной инструкции](CLOUDFLARE_SETUP.md) Cloudflare Worker и KV namespace `benzware-control`, подключённый к Worker как binding **`CONTROL`**. Если этого ещё нет, сначала пройдите раздел 1 основной инструкции.
- Доступ к Telegram, Cloudflare Dashboard и терминалу с `curl` (например, Termux на телефоне). **Никому не присылайте токен бота и секрет вебхука**, включая этот чат.
- **Не нужна новая Android-сборка**, если она уже собрана с адресом этого же Worker: `/status` остаётся прежним. После обновления Worker перепроверьте `/status` и работу команд.

## Шаг 1. Создать бота в Telegram

1. В Telegram найдите **@BotFather** (официальный бот с подтверждённым аккаунтом), откройте чат и отправьте `/newbot`.
2. На вопрос о названии напишите, например, `Benzware Control`. На вопрос об имени пользователя введите **уникальное** имя, оканчивающееся на `bot`, например `my_private_benzware_bot` (если занято, придумайте другое).
3. BotFather выдаст **токен бота** вида `123456789:ABC...`. Сохраните в менеджере паролей; не публикуйте в GitHub и не пересылайте никому. Если токен оказался раскрыт, перевыпустите его через BotFather (`/revoke`) и замените секрет в Cloudflare, затем повторно настройте вебхук.
4. Откройте в Telegram **вашего** бота и отправьте ему `/start`. Пока он может не отвечать — это нормально.

## Шаг 2. Узнать свой числовой Telegram ID (не имя @username)

До установки вебхука в терминале, где есть `curl`, введите токен **без отображения вводимых символов** (для bash/Termux):

```sh
read -r -s -p 'Вставьте токен бота: ' BOT_TOKEN; echo
curl -q -fsS "https://api.telegram.org/bot${BOT_TOKEN}/getUpdates"
```

В ответе JSON найдите сообщение `/start`, отправленное вами. Возле него будет `"from":{"id":123456789,...}` — запишите **свой номер после `from.id`**, например `123456789`. Не перепутайте с `update_id`, `message_id` или текстовым `@username`. Не присылайте весь ответ API другим людям: в нём могут быть сообщения. Если видите `"result":[]`, отправьте боту ещё одно сообщение и повторите `getUpdates`. Если Telegram сообщает, что нельзя использовать `getUpdates` при активном webhook, сначала удалите прежний webhook через BotFather/API либо используйте свой заранее известный числовой ID.

## Шаг 3. Обновить код существующего Cloudflare Worker

1. Откройте **Cloudflare Dashboard → Workers & Pages → ваш существующий Worker → Edit code**.
2. Полностью замените его код **актуальным содержимым** файла [`cloudflare/worker.mjs`](cloudflare/worker.mjs). Не создавайте новый Worker: приложение уже знает адрес старого.
3. Нажмите **Save and deploy**. Оставьте привязку KV с именем **`CONTROL`** без изменений.
4. В браузере откройте старый адрес Worker с `/status`. Он по-прежнему должен отвечать `enabled` либо `disabled`, а не `503`.

## Шаг 4. Добавить в Worker три настройки

На странице **того же Worker → Settings → Variables and Secrets → Add** добавьте:

| Имя | Тип | Значение |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | **Secret** | токен, который дал BotFather |
| `TELEGRAM_ADMIN_ID` | Text / обычная переменная | ваш числовой ID из шага 2, только цифры, например `123456789` |
| `TELEGRAM_WEBHOOK_SECRET` | **Secret** | новый случайный секрет не короче 32 символов |

Для последнего можно сгенерировать значение в терминале командой `openssl rand -hex 32` (если нет OpenSSL, используйте генератор паролей: 32+ символов **латинские буквы/цифры/`_`/`-`**). Сохраните секрет в менеджере паролей: он потребуется один раз для установки вебхука. Это **другой секрет**, не токен бота и не необязательный `ADMIN_TOKEN` от старого `/admin`. После добавления переменных **Save and deploy**, если Dashboard это предлагает. Ничего из таблицы, кроме публичного адреса Worker, не встраивается в Android-бинарь. В GitHub эти три значения добавлять не нужно.

## Шаг 5. Зарегистрировать вебхук Telegram (один раз)

В bash/Termux установите `curl`, например `pkg install curl`, затем выполните команды ниже. Подставьте **реальный HTTPS-адрес своего Worker без `/status`** в `WORKER_URL`. Если переменная `BOT_TOKEN` сохранилась в том же терминале после шага 2, вводить её повторно не нужно.

```sh
export WORKER_URL='https://ИМЯ-ВАШЕГО-WORKER.ВАШ-ПОДДОМЕН.workers.dev'
read -r -s -p 'Токен бота (если не вводили в этой сессии): ' BOT_TOKEN; echo
read -r -s -p 'TELEGRAM_WEBHOOK_SECRET из Cloudflare: ' HOOK_SECRET; echo
curl -q -fsS -X POST "https://api.telegram.org/bot${BOT_TOKEN}/setWebhook" \
  --data-urlencode "url=${WORKER_URL}/telegram" \
  --data-urlencode "secret_token=${HOOK_SECRET}" \
  --data-urlencode 'allowed_updates=["message"]' \
  --data-urlencode 'max_connections=1' \
  --data-urlencode 'drop_pending_updates=true'
```

Если токен уже был в переменной `BOT_TOKEN`, **пропустите строку `read ... BOT_TOKEN`**. Ответ должен содержать `"ok":true`. `HOOK_SECRET` должен совпадать с секретом в Cloudflare **символ в символ**. Webhook URL должен заканчиваться на **`/telegram`**, а не `/status`. Передача токена происходит только между вашим терминалом и HTTPS-серверами Telegram; однако на устройстве с доступом к списку процессов другие привилегированные программы могут увидеть аргументы `curl`. Выполняйте настройку в доверенной среде.

Затем проверьте регистрацию:

```sh
curl -q -fsS "https://api.telegram.org/bot${BOT_TOKEN}/getWebhookInfo"
```

В поле `url` должен быть ваш адрес `/telegram`. Если есть `last_error_message`, проверьте этот текст и настройки Worker. После настройки можно закрыть терминал или выполнить `unset BOT_TOKEN HOOK_SECRET`.

## Шаг 6. Проверить команды

1. Откройте **личный чат** со своим ботом, отправьте `/status`: ответ «Статус: выключено» или «Статус: включено».
2. Отправьте `/on`: ожидается «Включено…». Через некоторое время откройте в браузере `https://...workers.dev/status`: появится `enabled`.
3. Отправьте `/off`: ожидается «Выключено…». Спустя некоторое время `/status` Worker вернёт `disabled`, уже запущенный бинарь завершится при следующей проверке; новый запуск будет отклонён. Пока используется KV, распространение изменений может занять заметное время. Для быстрого переключения настройте [D1](CLOUDFLARE_SETUP.md#ускоренное-выключение-через-d1-рекомендуется); даже с D1 остаются период опроса и сетевой таймаут.
4. Отправьте `/help`, чтобы увидеть список команд. До миграции на D1 ключ также можно менять вручную через Cloudflare KV по [основной инструкции](CLOUDFLARE_SETUP.md#2а-самый-простой-выключатель-прямо-в-панели-cloudflare-без-команд).

## Если бот молчит

- **`getWebhookInfo` показывает пустой `url`** → повторите шаг 5.
- **Есть `last_error_message`** → перепроверьте HTTPS-адрес Worker, `/telegram` и работоспособность его публикации.
- **`/status` в браузере отвечает `503`** → проверьте binding KV `CONTROL` до миграции; после миграции — D1 `CONTROL_DB` и создана ли таблица.
- **Worker `/status` работает, бот молчит** → проверьте точные имена трёх настроек, числовой `TELEGRAM_ADMIN_ID` (это ваш `from.id`, не @username), совпадение `TELEGRAM_WEBHOOK_SECRET`, отправляете ли вы сообщения в **личный чат**, а также `TELEGRAM_BOT_TOKEN`.
- **Бот подтвердил `/on`, а браузер ещё показывает `disabled`** → на KV подождите распространения и обновите страницу; при D1 проверьте binding `CONTROL_DB` и что Worker обновлён. Бот и `/status` должны обращаться к **одному Worker**.

`/on`, `/off`, `/status` и `/help` — реализованный объём «управления». Добавление отдельных клиентов, лицензий, сроков доступа, статистики устройств или оповещений требует отдельного согласования правил. **Даже Telegram-выключатель не может гарантированно отключить изменённую кем-то копию бинаря.**
