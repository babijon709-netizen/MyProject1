# Непрерывный ESP при смерти и возрождении

## Исправленный жизненный цикл

`esp_get_boxes()` больше не публикует пустой кадр только потому, что во время смерти временно исчез список `PlayerManager` или ещё не появилась позиция нового локального игрока.

- Пустое чтение списка не уничтожает последний подтверждённый состав. Старые объекты читаются, пока игра не отдаст подтверждённый новый состав; неудачные чтения позиции удерживаются по монотонному времени до 5 секунд, независимо от 60/120/144 FPS.
- Полная замена population очищает только кэши конкретных объектов. Структурные параметры выбранной сборки — position field, формат camera matrix и раскладка Transform hierarchy — переживают обычный respawn и больше не переобучаются 1–2 секунды.
- Новый локальный `PlayerManager` сначала определяется по точному `Mirror.NetworkIdentity.isLocalPlayer`. Если объект локального временно отсутствует либо имеет `respawning`, расстояния считаются от актуальной позиции камеры; наблюдаемый противник больше не принимается за локального и не скрывается.
- Ранние разрывы camera/player pipeline дополнительно закрывает `EspContinuity`: последний полностью валидный набор player boxes удерживается до 10 секунд, но только когда текущий кадр совсем не содержит игроков. Боты не кэшируются. У резервных боксов отключены все aim/world points, поэтому этот визуальный fallback не может стать устаревшей целью аима.
- Снимок непрерывности очищается при настоящей потере процесса. Валидный пустой кадр с живым локальным игроком также очищает его, поэтому ушедшие с сервера игроки не остаются навсегда.

## Проверка

Host-тест `tools/esp/run.sh` воспроизводит последовательность `healthy → death gap → partial respawn → healthy respawn`, проверяет отсутствие пустого визуального кадра, запрет stale aim points, замену снимка и его очистку/таймаут.
