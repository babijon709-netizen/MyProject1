# benzware: удалённый выключатель через Cloudflare (бесплатный тариф)

## Что сделано и что **не** сделано

- Нативный исполняемый файл называется `benzware`, единый распространяемый файл — `benzware.sh` (внутри также лежит отдельный `benzhack_dump`). Имя NDK-модуля и артефакта GitHub Actions тоже изменено.
- До инициализации интерфейса и подключения к игре `benzware` запрашивает `GET /status` у вашего Cloudflare Worker. Ровно ответ `enabled\n` с HTTP **200** и успешной проверкой HTTPS разрешает старт. Пустая настройка, выключатель, ошибка сети, HTTP-ошибка, недоступный `curl` и любой неожиданный ответ запрещают запуск.
- Во время работы выполняется новая проверка раз в 10 секунд (в новых сборках); при отказе программа завершает основной цикл и освобождает ресурсы обычным путём. Это **не** моментальное выключение: учитывайте также сетевой таймаут до 10 секунд и задержку распространения изменений Cloudflare KV (может быть около минуты и более).
- В бинаре хранится лишь публичный URL `/status`. По умолчанию состояние KV отсутствует и считается выключенным. Токен `ADMIN_TOKEN` нужен **только если** хотите переключать доступ командами через `/admin`; при ручном управлении из панели Cloudflare его можно не создавать.
- Это контроль доступа для *неизменённого* бинаря, а не гарантия от взлома: человек с копией файла и контролем устройства может пропатчить проверку, заменить `curl`, подменить среду выполнения или собрать свой вариант. Не считайте выключатель средством отзыва уже раскрытого исходного кода и не храните в бинаре секреты. Отдельный дампер (`dump`) этим переключателем не блокируется.
- Нужны исходящий HTTPS и работающий `curl` на Android (например, из Termux) **в том же окружении / PATH, откуда запускается приложение под root**. `curl` без проверки сертификатов (`-k`) не используется. Без `curl` запуск намеренно не работает.

## Как это устроено — простыми словами

**KV** — маленькое хранилище Cloudflare с одним ключом `enabled`. **Worker** — опубликованная страница `/status`, которая читает этот ключ и отвечает одним словом. **GitHub Actions** собирает Android-файл, в котором записан адрес страницы `/status`. На телефоне новый файл спрашивает эту страницу перед запуском и каждые 10 секунд после него (старые сборки — каждые 30 секунд). Cloudflare не хранит ваш бинарь; он лишь отвечает «разрешено / запрещено». Сначала подключите Worker к KV, затем добавьте адрес Worker в GitHub, затем соберите файл.

## 1. Создать бесплатный Cloudflare Worker и хранилище

1. Войдите в [Cloudflare Dashboard](https://dash.cloudflare.com/) и выберите бесплатный план. Платный домен не нужен: используйте выданный адрес `https://<имя>.<ваш-поддомен>.workers.dev` (если предложено, включите поддомен `workers.dev`). Названия пунктов интерфейса Cloudflare могут слегка меняться.
2. В разделе **Workers & Pages → KV** создайте namespace, например `benzware-control`. Запомните именно его имя; пока никаких ключей вручную записывать не нужно.
3. В **Workers & Pages → Create → Worker** создайте Worker, например `benzware-control`, и разверните стартовый шаблон. Откройте его **Edit code**, замените весь шаблон текстом файла [`cloudflare/worker.mjs`](cloudflare/worker.mjs) и нажмите **Save and deploy**. При необходимости в редакторе оставьте формат Worker как *module* (код содержит `export default`).
4. В настройках **этого Worker** откройте **Settings → Bindings → Add binding → KV Namespace**. Имя переменной/binding в коде — **`CONTROL`** (регистр важен), namespace — созданный `benzware-control`. Сохраните и разверните изменение.
5. **Необязательно**: если хотите переключать доступ командами через `/admin`, сгенерируйте токен **локально**: `openssl rand -hex 32` (64 hex-символа). Сохраните его в менеджере паролей. В **Settings → Variables and Secrets → Add** добавьте **Secret** с именем **`ADMIN_TOKEN`** и значением этого токена; не выбирайте обычную видимую переменную. Сохраните/разверните изменение. **Не добавляйте токен в GitHub, исходники, URL или публичный чат.** Если будете переключать вручную в KV (раздел 2А), полностью пропустите этот шаг.
6. Скопируйте точный HTTPS-адрес Worker из Dashboard. Далее будем обозначать его `https://<ваш-worker>.workers.dev` (**угловые скобки — это пример, их не вводить**). Сначала откройте этот адрес с добавленным `/status` в обычном браузере. На белой странице должно быть слово `disabled`. Если умеете пользоваться терминалом, можно дополнительно проверить HTTP-код:
   ```sh
   curl -q -i 'https://<ваш-worker>.workers.dev/status'
   ```
   Должны быть HTTP `200` и тело `disabled`. Если `503` — проверьте binding `CONTROL`; если `404` — проверьте опубликованный код и путь `/status`.

## 2А. Самый простой выключатель: прямо в панели Cloudflare (без команд)

1. В Cloudflare Dashboard откройте **Workers & Pages → KV**, затем нажмите созданный namespace `benzware-control` (это **название хранилища**, а не обязательно название Worker). Найдите вкладку со списком ключей: **KV Pairs / Keys**.
2. Для **включения** нажмите **Add entry / Add key-value pair**: в поле **Key** введите точно `enabled`, в поле **Value** — точно `enabled` (маленькими буквами, без кавычек и пробелов). Сохраните.
3. Для **выключения** отредактируйте **значение этого же ключа** с `enabled` на `disabled` и сохраните. Если в вашем интерфейсе нет редактирования, удалите ключ `enabled` целиком — **отсутствующий ключ тоже означает «выключено»**. Не удаляйте namespace или Worker.
4. В новой вкладке браузера откройте `https://<ваш-worker>.workers.dev/status`. Увидите единственное слово `enabled` либо `disabled`. Если сразу после изменения видите старое значение — подождите и обновите страницу: KV распространяет изменения не мгновенно. Для более быстрого выключения перейдите на D1 по разделу ниже: после миграции этот ключ KV больше не используется. Новая сборка проверяет статус каждые 10 секунд; старая — каждые 30 секунд. **Этот способ не требует `ADMIN_TOKEN`, терминала или POST-запросов.**

## 2Б. Необязательный способ: переключать командами с токеном

Этот раздел нужен только если вы добавили секрет `ADMIN_TOKEN` в шаге 1.5. Никогда не вводите токен в строку URL и никому его не отправляйте.

1. Задайте URL (без завершающего `/`) и **введите** сохранённый токен, не вставляя его прямо в команду/историю терминала:
   ```sh
   export WORKER_URL='https://<ваш-worker>.workers.dev'
   read -r -s -p 'ADMIN_TOKEN: ' ADMIN_TOKEN; echo
   export ADMIN_TOKEN
   ```
   В некоторых shell опция `read -p` недоступна: тогда используйте `read -r -s ADMIN_TOKEN`, введя токен при скрытом вводе. Не запускайте команды с `set -x`.
2. Включить (`true`):
   ```sh
   curl -q -fsS -X POST "$WORKER_URL/admin" \
     -H "Authorization: Bearer $ADMIN_TOKEN" \
     -H 'Content-Type: application/json' \
     --data '{"enabled":true}'
   ```
   Ответ: `enabled`. Проверьте `curl -q -fsS "$WORKER_URL/status"` — в зависимости от кеша KV изменение может быть видно не сразу.
3. **Выключить когда угодно** (`false`):
   ```sh
   curl -q -fsS -X POST "$WORKER_URL/admin" \
     -H "Authorization: Bearer $ADMIN_TOKEN" \
     -H 'Content-Type: application/json' \
     --data '{"enabled":false}'
   ```
   Ответ: `disabled`. После распространения KV новые экземпляры не стартуют, работающие завершатся при очередной проверке. При ошибке Cloudflare или сети они тоже завершатся/не запустятся, поэтому доступность Worker важна. Если токен утёк, смените `ADMIN_TOKEN` в Cloudflare и в своём менеджере паролей.
4. После администрирования можно выполнить `unset ADMIN_TOKEN`. `/status` общедоступен **на чтение** и не требует токена; `/admin` доступен только по POST с секретом.

## Ускоренное выключение через D1 (рекомендуется)

Workers KV может показывать старое значение до истечения кеша; уменьшение частоты опроса бинаря **не решает** эту задержку. Бесплатная Cloudflare D1 читает состояние из основной базы без KV-кеша. Переключение после обновления Worker становится видимым обычно сразу при следующем запросе; гарантировать мгновенную остановку телефона нельзя (зависит от сети и периода опроса).

1. В Cloudflare Dashboard откройте **Storage & databases → D1 SQL database → Create Database**. Назовите базу `benzware-control-db` (название может быть любым). Платный тариф для D1 не обязателен; следите за бесплатными лимитами.
2. Откройте базу, вкладку **Console**. Выполните SQL из файла [`cloudflare/d1-schema.sql`](cloudflare/d1-schema.sql). Если консоль не принимает две команды вместе, выполните по одной: `CREATE TABLE ...` и затем `INSERT OR IGNORE ...`. Стартовое значение `0` — **выключено**.
3. Откройте **существующий Worker → Settings → Bindings → Add → D1 database**. Binding/Variable name — строго **`CONTROL_DB`**, база — `benzware-control-db`. Сохраните и разверните изменение.
4. В **Edit code** того же Worker замените код на актуальный [`cloudflare/worker.mjs`](cloudflare/worker.mjs), нажмите **Save and deploy**. Старая привязка KV `CONTROL` может остаться: при наличии `CONTROL_DB` Worker использует **только D1**. Если D1 не настроена/сломана, Worker вернёт HTTP 503 и бинарь откажет (без небезопасного возврата к старому `enabled` в KV).
5. Проверьте `/status`: сразу после миграции ожидается `disabled`. Затем отправьте боту `/on`, проверьте `/status` → `enabled`; отправьте `/off` → `disabled`. Редактирование **старого KV** после привязки D1 больше ничего не переключает. Для ручного выключения используйте в **D1 → Console**: `UPDATE benzware_control SET enabled = 0 WHERE id = 1;`.
6. Соберите новый `benzware.sh` из GitHub Actions и **замените** старый файл на устройстве: бинарь из прежних сборок продолжает проверять статус раз в 30 секунд, новая версия — раз в 10 секунд. Адрес Worker в переменной `BENZWARE_STATUS_URL` остаётся прежним, пересоздавать бота и webhook не нужно.

## 3. Подключить сборку в GitHub Actions

1. Откройте **репозиторий GitHub → Settings → Secrets and variables → Actions → Variables → New repository variable**. Добавьте **`BENZWARE_STATUS_URL`** со значением **`https://<ваш-worker>.workers.dev/status`** (без пробелов и кавычек). Это *публичный адрес*, не секрет; `ADMIN_TOKEN` в GitHub **не нужен**.
2. После настройки переменной отправьте изменения **только** в рабочую ветку этого сеанса (если работаете локально в этом репозитории):
   ```sh
   git status --short
   git add -A
   git commit -m "Add benzware Cloudflare remote switch"
   git push origin arena/01a0d845-myproject1
   ```
   Проверьте, что в `git status` не попал ваш административный токен. Если изменения уже опубликованы через интерфейс Arena, повторный коммит не нужен. При необходимости откройте PR **из этой ветки**. Новый push либо **Actions → Build benzware.sh → Run workflow** запускает сборку. При необходимости разрешите GitHub Actions в настройках репозитория. **Без** переменной `BENZWARE_STATUS_URL` сборка намеренно завершается ошибкой, вместо публикации файла, который никогда не сможет стартовать.
3. Дождитесь зелёного задания `Android arm64-v8a`. В его **Artifacts** скачайте `benzware-sh-arm64-v8a`, распакуйте архив Actions: внутри `benzware.sh`. Не скачивайте старые артефакты: их проверки и имена не меняются задним числом.
4. Для локальной сборки вместо Actions: установите Android NDK версии, совместимой с проектом (в CI — `26.3.11579264`), затем:
   ```sh
   export ANDROID_NDK_HOME='/путь/к/android-ndk'
   export BENZWARE_STATUS_URL='https://<ваш-worker>.workers.dev/status'
   ./build.sh
   ```
   Результат: `libs/arm64-v8a/benzware` (сам бинарь) и `libs/arm64-v8a/benzware.sh` (распространяемый файл). `build.sh` создаёт игнорируемый Git-файл `jni/include/benzware_remote_local.h` с **публичным** URL. Перед сменой Worker пересоберите и перераспространите файл. Перед первой сборкой включать доступ необязательно: Worker по умолчанию выключен.

## 4. Подготовить Android и запустить

1. Нужен Android `arm64-v8a` с уже работающим для этого проекта root-окружением и доступом к интернету. Установите Termux и в нём `pkg update && pkg install curl`. Убедитесь, что `curl --version` работает.
2. **Под тем же пользователем/root, которым будете запускать программу**, проверьте `curl` и сертификаты, например из Termux:
   ```sh
   su -c 'PATH=/data/data/com.termux/files/usr/bin:/system/bin:/system/xbin curl -q -fsS https://<ваш-worker>.workers.dev/status'
   ```
   Ожидается `enabled` (после включения) либо `disabled`. Если `curl: not found` — исправьте PATH/установку Termux; если ошибка сертификата — исправьте часы или хранилище CA, **не** используйте `-k`. Путь Termux может отличаться при нестандартной установке.
3. Передайте `benzware.sh` на устройство (например, `adb push benzware.sh /data/local/tmp/benzware.sh`), выставьте права: `adb shell su -c 'chmod 700 /data/local/tmp/benzware.sh'`.
4. Запустите из Termux/root-терминала с правильным PATH:
   ```sh
   su -c 'PATH=/data/data/com.termux/files/usr/bin:/system/bin:/system/xbin /data/local/tmp/benzware.sh'
   ```
   Для встроенного отдельного дампера сохранена форма `.../benzware.sh dump [аргументы]`. Временная распаковка идёт в приватный каталог `${TMPDIR:-/data/local/tmp}` и удаляется после выхода скрипта.
5. Пока используется KV, выключите доступ по разделу 2А (в панели KV) или 2Б (командой) и учитывайте задержку распространения KV. После перехода на D1 используйте бота либо SQL-консоль D1: при очередной проверке новая сборка остановится (до 10 с ожидания опроса плюс до 10 с сетевого таймаута). Повторный запуск при `disabled` должен вывести `benzware: remote authorization unavailable or disabled` и закончиться с кодом `1`.

## Проверки и диагностика

- Без Android NDK: `node tests/remote_gate/worker.test.mjs` и `sh tests/remote_gate/native.test.sh` — тестируют Worker и стартовую проверку бинаря с фиктивным `curl`; реальную сеть не используют. Дополнительно: `sh tools/hostcheck/run.sh`.
- `401` на `/admin`: неверный токен или он не сохранён как `ADMIN_TOKEN`; `415`: нет заголовка JSON; `503`: нет/не работает KV-binding `CONTROL` (до миграции), либо D1-binding `CONTROL_DB` / таблица базы (после миграции).
- Если `/status` уже `enabled`, но Android отказывает: убедитесь, что именно **root** видит настоящий `curl`, может разрешить DNS и доверяет HTTPS-сертификату; проверьте, что в собранном бинаре прописан URL нужного Worker, а ответ `enabled` приходит без редиректа. Сборка не содержит резервного «автономного режима».
- Частота проверки — около 8 640 запросов за сутки *на постоянно работающий экземпляр*. Следите за лимитами бесплатного тарифа Worker/KV/D1 в Dashboard; при большом числе одновременных экземпляров потребуется иная архитектура или тариф.
