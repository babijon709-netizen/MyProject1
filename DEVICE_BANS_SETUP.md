# Блокировка устройств по ID через Telegram

⚠️ Настройка обязательна **до установки новой сборки**. Блокировка работает только для новой версии `benzware.sh` и требует Cloudflare D1. Старые файлы продолжают проверять лишь общий `/status` и не знают про баны.

## 1. Cloudflare D1

В том же Worker, что отвечает по `/status`, должен быть D1 binding с точным именем `CONTROL_DB` (см. [инструкцию по D1](CLOUDFLARE_SETUP.md#ускоренное-выключение-через-d1-рекомендуется)). Если базы ещё нет, создайте её, выполните **весь** `cloudflare/d1-schema.sql` и настройте binding.

Если база уже работает с `/on` и `/off`, откройте **D1 → benzware-control-db → Console** и выполните только добавление таблицы устройств:

```sql
CREATE TABLE IF NOT EXISTS benzware_devices (
  hwid TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  banned INTEGER NOT NULL DEFAULT 0 CHECK (banned IN (0, 1)),
  first_seen TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

Таблица хранит псевдонимный HWID (SHA-256), отображаемое имя и флаг бана. Исходный Android ID и серийный номер **не сохраняются в Cloudflare и не передаются по сети**.

## 2. Обновить код существующего Worker

В Cloudflare Dashboard откройте **существующий** Worker → **Edit code**, полностью замените код содержимым актуального `cloudflare/worker.mjs` из ветки `arena/01a0d845-myproject1`, нажмите **Save and deploy**. Binding `CONTROL_DB`, `TELEGRAM_ADMIN_ID`, `TELEGRAM_BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET` оставьте прежними. Адрес Worker и webhook Telegram не меняются. Без D1 новая сборка не получит разрешения на запуск (fail closed).

После публикации `/status` по-прежнему показывает только **общий** включатель. Новые клиенты также используют nonce в `POST /auth`; старые клиенты без nonce перестанут запускаться после обновления Worker. См. [порядок обновления](TAMPER_LIMITS.md). Он не показывает индивидуальный бан.

## 3. Установить новую сборку на Android

В GitHub Actions скачайте **самый новый** `benzware-sh-arm64-v8a` после этого обновления, распакуйте ZIP и замените файл `/data/local/tmp/benzware.sh`. Старые копии удалите/не запускайте. При первом запуске устройство передаёт в Worker только хеш идентификатора и имя; Worker записывает его в D1 и присылает администратору Telegram-сообщение с именем устройства и полным HWID. Для полноценного запуска общий переключатель должен быть `/on` и устройство не должно быть забанено.

Имя берётся из системного `device_name`, при отсутствии — из производителя и модели Android. Идентификатор вычисляется из Android ID; при недоступности — из системного boot serial. Изменение имени не меняет HWID. Сброс устройства, изменение Android ID или серийного номера может **изменить HWID**. Это не криптографическая аттестация устройства: при root-доступе или изменённом бинаре ID можно подделать; нельзя обещать защиту от обхода.

## 4. Команды в личном чате с ботом

- `/devices [страница]` — все зарегистрированные устройства, по 8 на страницу: имя, полный HWID и значок активности/бана. `/devices 2` показывает следующую страницу.
- `/online [страница]` — разрешённые незабаненные устройства, чей `/auth` был успешен за последние 210 секунд; по 8 на страницу. Это не подтверждение, что человек в игре, и не список Telegram-аккаунтов.
- `/stats` — количество зарегистрированных, недавно активных и заблокированных устройств.
- `/device <HWID>` — карточка устройства с именем, баном и последней видимой активностью.
- `/ban <HWID>` — запретить одному устройству запуск и остановить уже запущенный новый бинарь при следующей проверке (до 60 секунд до очередной проверки плюс время сетевого ответа). Вставьте **полный 64-символьный HWID** из `/devices` или уведомления «Новое устройство».
- `/unban <HWID>` — убрать бан. Чтобы устройство вновь могло запуститься, общий выключатель `/on` тоже должен быть включён.
- `/on`, `/off` — общий выключатель для **всех** устройств; `/status` — состояние общего выключателя и краткая статистика устройств.

Пример: в ответе `/devices` есть `HWID: aaaa...` (64 символа). Скопируйте значение целиком и отправьте боту `/ban aaaa...`. Бот ответит «Устройство заблокировано». Не ставьте двоеточие, угловые скобки и многоточие вместо настоящего HWID.

Для нового меню и присутствия в уже работающей D1 сначала выполните SQL-миграцию и обновите Worker по [пошаговой инструкции](TELEGRAM_BOT_SETUP.md#обновление-уже-работающего-бота-онлайн-и-новое-меню). Новая Android-сборка для **этих** функций не требуется, если она уже использует `/auth`.

## Если не работает

- Бот говорит «Для управления устройствами привяжите D1 как CONTROL_DB» — нет binding `CONTROL_DB` или опубликован старый код Worker.
- `/devices` пуст — ещё не запускали **новую** сборку на устройстве, либо нет таблицы `benzware_devices`.
- Новая сборка пишет `device ID unavailable` — проверьте на **самом телефоне** `su -c '/system/bin/settings get secure android_id'`; не отправляйте никому его значение. Проверьте также `getprop ro.boot.serialno`. Если оба недоступны, требуется иной источник стабильного ID для этого Android.
- `/status` показывает `enabled`, а новый бинарь не стартует — проверьте D1 binding, схему таблицы, наличие бана в `/devices`, сетевой доступ root-окружения к Worker. Только `GET /status` уже недостаточно: новая сборка использует `POST /auth` для проверки конкретного устройства.
- Бот отвечает «Устройство заблокировано», но старый файл продолжает работать — обновите бинарь. Блокировка устройств **не действует на старые сборки**, выпущенные до внедрения этой проверки.

**Приватность:** имя устройства и хеш постоянного идентификатора сохраняются в вашей Cloudflare D1 и показываются администратору бота. Сообщайте об этом пользователям до распространения новой сборки. При необходимости удалите запись вручную в D1; не публикуйте список HWID третьим лицам.
