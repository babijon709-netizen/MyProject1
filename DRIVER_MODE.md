# Режимы KERNEL / NONKERNEL

При запуске софт показывает одно окно — выбор режима. Всё.

## Режимы

| | KERNEL | NONKERNEL |
|---|---|---|
| Чтение памяти | **только прямые syscalls `process_vm_readv/writev`** — копирование выполняет само ядро | те же syscalls, при отказе — `/proc/<pid>/mem` |
| Запасные пути | **нет** — отказ syscall пишется в лог, тихого перехода на «обычное чтение» не происходит | есть |
| Требования | root (софт сам перезапускается через su при старте) | root для чужого процесса |

## Про драйвер

Есть два независимых пути:

1. **`bw_mem.ko` — собственный драйвер benzware** (рекомендуемый): свой
   приватный протокол ioctl (`/dev/bwmem`), собирается в CI из исходников
   в `kernel_driver/`, чтение через `access_process_vm` в ядре.
2. FT-драйвер — сторонний (см. ниже), ручная установка.

### Свой драйвер bw_mem — ВРУЧНАЯ загрузка

Драйвер **встроен в сам бинарник** (собирается в CI из `kernel_driver/`,
зашивается массивом байт). Отдельный артефакт не нужен.

1. Скачай обычный артефакт `xvcen-sh-arm64-v8a` (как для софта) и положи
   `xvcen.sh` в `/data/local/tmp/`.
2. От root (MT Manager / Termux):
   ```
   /data/local/tmp/xvcen.sh --loadmod
   ```
   Софт извлечёт встроенный `bw_mem.ko` в `/data/local/tmp/`, загрузит его
   в ядро (обходя vermagic/CRC-проверки кастомного ядра), сделает PING и
   **самотест** — прочитает собственную память через драйвер. Результат —
   в терминале и в `benzware.log`.
3. Необязательный параметр — имя устройства:
   `--loadmod name=nevidimka` → `/dev/nevidimka`.
   Можно загрузить и внешний .ko: `--loadmod /data/local/tmp/bw_mem.ko`.
4. Драйвер живёт до перезагрузки. Выгрузка:
   ```
   /data/local/tmp/xvcen.sh --unloadmod
   ```
5. Если `--loadmod` сообщил ошибку — пришли вывод команды и `dmesg | tail -20`.

Никакой автоматической установки/поиска драйвера софт не делает — только
по явной команде `--loadmod`.

### FT-драйвер (сторонний)

Важно из замеров на устройстве: драйвер НЕ открывает обычный syscall-путь
для непривилегированных процессов (проверка от uid 2000 с прошитым
драйвером даёт EPERM) — у него свой закрытый клиентский протокол.
Поэтому KERNEL-режим в софте — это строгий путь чтения только прямыми
syscalls от root, без запасных вариантов.

## Установка FT-драйвера — ВРУЧНАЯ

Софт больше ничего не устанавливает и не запускает сам. Если нужен FT-драйвер
в ядре — прошей его один раз сам:

1. Возьми скрипт под свою версию ядра из `FTDriver.zip`
   (посмотреть версию: `uname -r`, у тебя было `5.10.255-...` → `5.10.sh`).
2. Скопируй в `/data/local/tmp/` (MT Manager / adb).
3. Выполни от root:
   ```
   su -c "sh /data/local/tmp/5.10.sh"
   ```
   Ответ `已刷入驱动无需重复刷入` = «драйвер уже прошит, повторно не нужно».
4. Драйвер живёт до перезагрузки телефона — после ребута прошей заново.

Внимание: эксплойты FT писались под стоковые ядра. На кастомных сборках
(SuiKernel и т.п.) скрипт может не подняться — это видно по его выводу.

## Проверка, что чтение идёт от ядра

В логе `/sdcard/Download/benzware.log`:

```
KERNEL: память читается напрямую через ядро (process_vm syscall, uid=0)
```

Чтение идёт прямым syscall (копирование выполняет ядро), без запасных путей.

В логе `/sdcard/Download/benzware.log` после подключения к игре в KERNEL-режиме
появляется строка:

```
KERNEL: память читается напрямую через ядро (process_vm syscall, uid=0)
```

Если бы чтение шло «как раньше, через обычное чтение» (`/proc/<pid>/mem`),
в KERNEL-режиме такой строки не будет — вместо неё писалась бы ошибка
`process_vm отказал (errno ...)`.

## Root

Софт рассчитан на запуск от root: при старте сам перезапускается через su
(если запущен обычным пользователем). Без root память игры не читается
ни в одном режиме — в логе будет `не могу подключиться к игре ... софт без root`.

## Диагностика

* `/sdcard/Download/benzware.log` — лог: запуск, режим, подключение к игре,
  результат чтений. При переполнении (~1.2 МБ) старый становится `benzware.log.1`.
