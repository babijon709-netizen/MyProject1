# Режимы запуска: NONKERNEL / KERNEL

При каждом запуске софт показывает **стартовое окно выбора режима**:

| Кнопка | Что делает |
|---|---|
| **KERNEL** | работа «от ядра» телефона: поднимается FT-драйвер (FTDriver.zip), память игры читается/пишется через ядро |
| **NONKERNEL** | обычный режим, как раньше: прямые `process_vm_readv/writev` (нужен root/ptrace-доступ к игре) |

## KERNEL-режим — как это работает

1. Софт читает `uname()` и определяет версию ядра телефона (например `5.10.136-android12`).
2. В папке драйверов подбирается скрипт из **FTDriver.zip**:
   * точное совпадение `x.y.z` (например `5.10.136.sh`);
   * иначе генерик под ветку (`5.10.sh`, `6.6.sh`, ...);
   * иначе соседний патч той же ветки `x.y.*`;
   * вендорские сборки (`-ColorOS`, `oneplus`, `oppo...`) предпочитаются на
     соответствующих прошивках (OPPO/realme/OnePlus);
   * варианты `b`/`c` используются как запасные.
3. Скрипт копируется в `/data/local/tmp/ftdrv_<имя>.sh` (если лежит не там —
   su-шелл может не видеть `/sdcard`) и запускается через **su**
   (`su -c "sh ..."`, либо напрямую, если софт уже запущен от root).
   Вывод драйвера пишется в `/data/local/tmp/ftdrv.log`.
4. Софт ждёт (до 40 сек), пока память игры начнёт читаться, и показывает
   статус на экране загрузки. Если игра ещё не запущена — через ~12 сек
   драйвер считается поднятым без проверки (attach-поток проверит сам).

Дальше весь обмен с памятью идёт через ядро:

```
process_vm_readv/writev  ──✕──►  /proc/<pid>/mem (pread/pwrite)
        (основной путь)          (автоматический запасной путь)
```

Если основной путь закрыт, модуль драйвера сам переключается на
`/proc/<pid>/mem` и дальше работает через него (без лишних syscall'ов —
рабочий путь запоминается). В NONKERNEL-режиме поведение прежнее:
только `process_vm_*`, без запасных путей.

## Что где лежит

```
jni/include/driver.h     — интерфейс модуля (driver::readv/writev, режимы)
jni/src/driver.cpp       — подбор скрипта, запуск через su, память, статусы
jni/src/game.cpp         — remote_vm_readv/writev перенаправлены в driver::
jni/src/main.cpp         — стартовое окно NONKERNEL/KERNEL + бейдж режима
FTDriver.zip             — скрипты драйвера (35 шт., 4.9 — 6.12)
```

## Сборка и установка

```bash
./build.sh
# build.sh сам распакует FTDriver.zip в libs/arm64-v8a/drivers/ft/
```

На телефон кладём бинарь **и** папку драйверов:

```bash
adb push libs/arm64-v8a/xvcen.sh      /data/local/tmp/
adb push libs/arm64-v8a/drivers       /data/local/tmp/   # получится /data/local/tmp/drivers/ft/*.sh
adb shell chmod +x /data/local/tmp/xvcen.sh
```

Софт ищет скрипты драйвера по порядку:

1. `<папка бинаря>/drivers/ft/` — стандартное место (см. выше);
2. `<папка бинаря>/drivers/`, `<папка бинаря>/ft/`, `<папка бинаря>/`;
3. `/data/local/tmp/drivers/ft/`, `/data/local/tmp/ft/`, `/data/local/tmp/`;
4. `/sdcard/Download/drivers/ft/`, `/sdcard/Download/ft/`, `/sdcard/Download/`.

## Требования KERNEL-режима

* **root** (su): Magisk / KernelSU / APatch — любой, дающий `su -c`;
* скрипт под версию ядра телефона в одной из папок поиска выше
  (нет скрипта или su — стартовое окно честно об этом скажет и предложит
  NONKERNEL);
* FT-драйвер патчит ядро до перезагрузки: после ребута телефона драйвер
  нужно поднять заново (просто выбрать KERNEL ещё раз).

## Автоматический root (с версии после 722747b)

Память игры читается только с правами root (или после патча ядра).
Если бинарник запущен обычным пользователем и на телефоне есть su,
софт **сам перезапускается от root** при старте:

* сначала тихо проверяет `su -c id` (до 6 секунд — успей ответить на
  диалог Magisk/KSU, если он появится);
* если root выдан — запускает root-копию себя (`su -c "<бинарник> --rooted"`),
  и исходный процесс завершается (в /proc он больше не висит);
* если root не выдан — продолжает как есть, и на стартовом окне увидишь
  красную строку `Root: нет`. Тогда оба режима не смогут читать память
  игры — выдай доступ su и запусти заново.

Ручной запуск от root (`su -c ...`) по-прежнему работает и ничего не
меняет — эскалация просто не потребуется.

## Диагностика

* **Лог в «Загрузках»: `/sdcard/Download/xvcen.log`** — главный файл
  диагностики. Туда пишется всё: запуск и uid, результат root-эскалации,
  выбранный режим, запуск скрипта драйвера, подключение к игре (pid),
  ошибки чтения памяти, а также **зеркало вывода скрипта** из
  `/data/local/tmp/ftdrv.log` (сами `/data`-файлы без root не прочитать).
  Забирается любым файловым менеджером или MTP — adb и root не нужны.
  При переполнении (~1.2 МБ) старый лог переименовывается в
  `xvcen.log.1`;
* `/data/local/tmp/ftdrv.log` — вывод скрипта драйвера (хвост видно прямо
  на экране загрузки KERNEL);
* в меню справа в шапке — бейдж `KERNEL` / `NONKERNEL` с точкой:
  зелёная — игра реально подключена (память читается), жёлтая — ещё нет;
* вкладка «Опции» → секция «Диагностика»: режим, root, версия ядра,
  состояние драйвера и его скрипт, pid игры, счётчики чтений
  (process_vm / proc-mem / ошибки) и путь лога — весь статус одним
  списком прямо на телефоне;
* на экране загрузки KERNEL видно: версию ядра, выбранный скрипт,
  статус root, pid игры (запущена/нет), прошедшее время и хвост лога
  драйвера — по этому экрану сразу понятно, на каком шаге проблема;
* если ядро телефона не покрыто FTDriver — на экране загрузки будет
  точная версия (сравни с именами `.sh` в архиве и положи недостающий
  скрипт в папку поиска).
