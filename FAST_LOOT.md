# Быстрый подбор штатной кнопкой

## Использование

1. Включить **«Разное → Быстрый подбор»**.
2. Открыть ящик обычным способом.
3. Нажать **штатную кнопку сбора всех предметов** в игровом окне контейнера.

По уточнённому выбору пользователя отдельная кнопка оверлея не добавляется. Настройка сама не начинает сбор, не открывает ящики и не переносит предметы на расстоянии. По умолчанию выключена; сохраняется в профиле.

Заданная пауза между переносами теперь **0 с** вместо штатных 0,35 с и прежнего ускоренного значения 1 мс. Это убирает таймерную задержку, но не обещает перенос всего ящика за один кадр: штатная обработка `WaitForSeconds(0)`/PlayerLoop и сервера остаётся, как и проверки места в инвентаре. Синхронный цикл отправки всех запросов не добавляется. После выключения возвращается обычная пауза; уже запущенное ожидание текущего предмета не пересоздаётся.

Штатный контроллер сбора общий для нескольких видов контейнеров: ускорение может применяться и к их кнопкам сбора. Обратная операция «загрузить всё в контейнер» (`FastLoadAll`) не изменяется. Проверки наличия предмета/места, выбор слота, команды инвентаря и отмена при закрытии окна остаются штатными. Не изменяются item count, сетевые ID, копии инвентаря или серверные права.

## Подтверждение по исходным образам

В `LootScreenViewImpl` есть `collectButton` (+0x48) и отдельный `fastLoadButton` (+0x50). `LootScreenPresenter` получает `xg collectLootController`; `xg` реализуется классом `xw` (релиз) / `vB` (бета). Тот же контроллер используется старыми LootOpener и некоторыми другими окнами контейнеров.

| | Релиз | Бета |
|---|---:|---:|
| libil2cpp GNU build ID | `d85e63cd8dcbd481695012ef2e284f0eeb9ef307` | `e10795349bd7c2cdc7d8527597c64395a4efed79` |
| `CollectAllItems.MoveNext` RVA | `0x5B5C5BC` | `0x5AF47EC` |
| Инструкция загрузки задержки RVA | `0x5B5CAD4` | `0x5AF4D04` |
| Исходный float 0.35 RVA | `0x213A950` | `0x2137000` |
| `UniTask.WaitForSeconds` RVA | `0xC3290B4` | `0xC30B670` |

Исходная инструкция — `LDR S0,[X8,...]`, аргумент `duration` для `UniTask.WaitForSeconds(float,bool,PlayerLoopTiming,CancellationToken,bool)`. Меняется **одна выровненная 4-байтовая инструкция** на `FMOV S0,WZR` (`0x1E2703E0`). Нулевые биты WZR дают точный float **+0.0**, а `WaitForSeconds` — таймер 0 мс. Остальные аргументы, вызовы переноса, цикл, ожидание и cancellation token не меняются. **Общий float 0.35 в пуле констант не перезаписывается**: его могли использовать другие методы.

**Совместимость процессора:** используется базовая инструкция ARM64. Требование FEAT_FP16/ASIMDHP от предыдущего варианта 1 мс удалено. Проверка архитектуры, build ID и соседнего кода сохранена.

Это патч исполняемого кода игры, в отличие от параметров FOV/рук/FPS. Запись идёт существующим `/proc/<pid>/mem`, который на стандартном Linux/Android arm64 выполняет cache maintenance через kernel `copy_to_user_page`. Очистка локального instruction cache для чужого виртуального адреса не используется. Если запись запрещена ядром/SELinux, функция сообщает об ошибке, не пытается менять защиты страницы или обходить ограничение другим способом.

## Контроль версии и восстановление

- До записи сверяются все 20 байт GNU build ID и 8 инструкций вокруг места изменения.
- В неизвестную версию, изменённый соседний код или чужую инструкцию запись не выполняется.
- Уже установленный не этим экземпляром контроллера патч не присваивается себе.
- После записи читается фактическая инструкция. Постоянной перезаписи кода каждый кадр нет; проверка — раз в 250 мс, переключение — сразу.
- Выключение восстанавливает только свою инструкцию; ошибки восстановления повторяются при последующих тиках.
- На штатном выходе/смене сборки выполняется попытка восстановления с проверкой образа; ошибка пишется в лог. При потере процесса адрес забывается без записи.
- После принудительного убийства оверлея восстановление не гарантируется: для возврата исходного кода может понадобиться перезапуск игры.
- Выполнение синхронизировано существующим mutex сессии. Функция не зависит от ESP и не требует локального игрока для определения native-образа.

Настройка занимает бит 4 (`16`) flags в существующем 32-байтовом расширении VMW1 v1. Старые профили с flags 0–15 загружают её выключенной. Старое приложение, не знающее этот бит, отклонит расширение с ним и загрузит его значения по умолчанию; основной конфиг v4 не менялся. «Сброс» под FOV/руками не меняет быстрый подбор или FPS.

## Проверки и ограничения

```sh
sh tools/fast_loot/run.sh
python3 tools/fast_loot/check_native.py /path/to/release/libil2cpp.so /path/to/beta/libil2cpp.so
sh tools/viewmodel/run.sh
sh tools/lang/run.sh
sh tools/hostcheck/run.sh
```

Стенд запускается из `build.sh` перед NDK-сборкой. Проверены оба образа, исходная константа, кодировка ARM64 FMOV S0,WZR и точный нулевой аргумент, преобразование в 0 мс внутри WaitForSeconds, отказ на неподдерживаемой архитектуре, неизвестный образ/чужой код, повторное включение без перезаписи, выключение и normal-exit restore, ошибки чтения/записи/readback и retry, потеря сессии и смена базы. Отдельный процесс-ребёнок держит RX-страницу: настоящий `memio::Reader` устанавливает и возвращает инструкцию через `/proc/pid/mem`, ребёнок подтверждает видимые байты. Конфиг проверяется вместе с FOV/руками и всеми режимами FPS.

**Android-устройство в этой среде не подключено.** Проверка RX-страницы на хосте не исполняет ARM64-инструкции и не заменяет проверку instruction cache/игрового поведения на телефоне. Пользователь подтвердил работу предыдущего варианта 1 мс. Новый вариант с нулевой паузой пока не проверен на устройстве.

При обновлении штатно закрыть старый оверлей с восстановлением патча. Если он был убит принудительно, перезапустить игру: код от предыдущего экземпляра (включая патчи 1 мс / 0,125 с) намеренно не перезаписывается новым контроллером.

На устройстве проверить: ящик с несколькими стаками; пустой ящик; полный инвентарь; закрытие окна посреди сбора; повторное открытие другого ящика; отключение функции; смена профиля/версии; нормальный выход. Сравнить содержимое после повторного открытия, а не только локальную анимацию. При ошибке применения смотреть `fast-loot: status=4` в логе.
