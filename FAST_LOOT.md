# Быстрый подбор: патч удалён, отдельный модуль — прототип

По требованию не изменять libil2cpp.so и другие библиотеки прежний контроллер
подбора и его переключатель удалены. В основной сборке **ускоренного подбора нет**;
штатная кнопка игры работает штатно. Профильный бит 4 игнорируется и не сохраняется.

После отдельного согласия на внутрипроцессное исследование добавлен
[экспериментальный модуль](experimental/loot_module/README.md). Он содержит
синхронное ядро, адаптер и API привязки к heap-делегату штатной кнопки. **Загрузчик
и безопасная начальная привязка в игре не готовы; это не рабочая интеграция
мгновенного подбора в оверлей.** Обычная сборка не превращается во внедряемую.

## Почему нет равноценной замены

Ранее один ARM64-переход пропускал весь межпредметный await. Это позволяло клиенту
отправлять обычные запросы переноса одним проходом, но было патчем инструкций.
Запись нуля в таймер не равнозначна пропуску await: сохраняются переходы между
кадрами. Пользователь уже отклонил такой вариант как недостаточно мгновенный.

Исследование двух имеющихся дампов подтвердило:

- `xw` (release) / `vB` (beta), CollectAllItems: задержка 0.35 — literal, а не
  изменяемое поле контроллера. Нельзя заменить её в библиотечных константах,
  поскольку это также нарушает ограничение.
- Объект `UniTask.DelayIgnoreTimeScalePromise` имеет duration +0x18, elapsed +0x1C,
  cancellationToken +0x28 и completion core +0x50.
- Возможен исследовательский путь через `PlayerLoopHelper.runners` →
  `PlayerLoopRunner.loopItems` → promise → core.continuationState (System.Action)
  → target AsyncUniTask<CollectAllItems> → stateMachine. Run RVA —
  release 0xB403D10 / beta 0xB3E1170; начало stateMachine в runner — +0x20.
- Важно: continuationState — **делегат**, не сам state-machine runner.
- Изменение elapsed может ускорить только следующее возобновление. Оно не
  превращает операцию в мгновенный пакет; кроме того, pooled promise требует
  защиты от повторного использования и смены token/awaiter.

Этот путь **не реализован**. Не изменяются глобальный scheduler, timeScale,
указатели продолжений или библиотеки. Нет новой кнопки оверлея, удалённого
открытия контейнеров либо обхода серверных проверок. Вопрос о согласии на
покадровый вариант был пропущен; он не включён вместо ранее отклонённого поведения.

## Переход со старой версии

Остановить старый процесс инструмента и полностью перезапустить игру.
Удаление исходников не отменяет патч, уже оставшийся в работающем процессе.
Новая версия намеренно не содержит «очистки» посредством записи в библиотеки.
Новые оружейные функции проверяют старые точки патчей **только чтением** и
отказываются включаться, если инструкции не оригинальные.

## Дополнительная проверка штатных пакетных путей

- `MovePlanKind.MoveAll` не означает перенос всех слотов контейнера. Планировщик
  принимает пару `SlotSnapshot from/to` и amount; это перенос всего стака одного
  исходного слота (release `euz.FYG`, RVA 0x670BBA0).
- В `CollectAllItems.MoveNext` вызов на 0x5B5CAB0 идёт в
  `PlayerInventory.FYj(ContainerKind, int)` (0x670E610): вид контейнера и индекс
  одного слота. После него безусловно создаётся межпредметное ожидание.
- `CollectAllButton.Jwv` (0x6883B2C) действительно обходит слоты без await, но
  только считает непустые и обновляет interactable кнопки. Переноса там нет.
- `FastLoadAll` тоже не готовая синхронная замена: его MoveNext вызывает
  WaitForSeconds на 0x5B5D164.

По этим кандидатам переключатель «batch» в изменяемых данных не найден.
Отдельный механизм исполнения в игровом потоке теперь вынесен в
`experimental/loot_module/`: он меняет только `UnityAction.invoke_impl` в куче,
а не инструкции/данные библиотеки. Обычные запросы переноса выполняются одним
проходом без межпредметного ожидания. Смена контекста/отмена останавливает проход;
после потенциально отправленного запроса нет повторной штатной корутины.

Проверены host-ядро (-O0/-O3), сборка/загрузка host DSO и ARM64 ABI делегата в
Unicorn на оригинальных release/beta ELF. Это не Android-тест: остаются загрузчик,
безопасный UI bootstrap, реальный жизненный цикл и серверное подтверждение.
См. README модуля с ограничениями и командами сборки. Защита от бана не обещается.

Статус задачи: есть отдельный исследовательский прототип; **готового сквозного
мгновенного подбора в приложении по-прежнему нет**.
