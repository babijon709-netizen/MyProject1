# Защита benzware: лицензии, удалённое отключение, антитампер

Система из двух частей:

| Часть | Файл | Что делает |
|---|---|---|
| Клиент | `jni/src/license.cpp` | Проверка ключа при запуске, heartbeat, kill-switch, анти-отладка, самопроверка ELF |
| Сервер | `server/server.js` | Ключи, привязка к устройству (HWID), срок действия, бан, глобальный выключатель. Node.js без зависимостей |

Подключено в `jni/src/main.cpp` (`prot::Init()` → `license::Gate()` + проверка
`license::Dead()` в главном цикле), сборка — `src/license.cpp` в `jni/Android.mk`,
CRC-патч бинаря — шаг `tools/protect/patch_crc.py` в `build.sh`.

---

## 1. Быстрый старт

### Настройка (один раз, с телефона, ноутбук не нужен)

Реальный секрет и адрес сервера **в репозитории не лежат**: CI подставляет их в
`license.cpp` при сборке из GitHub Secrets (`tools/protect/inject_settings.py`).
Всё настраивается тремя секретами в веб-интерфейсе GitHub
(**репозиторий → Settings → Secrets and variables → Actions → New repository secret**):

| Секрет | Что вписать |
|---|---|
| `FLY_API_TOKEN` | Токен с fly.io: Dashboard → Account → Access Tokens → Create token |
| `BZW_SECRET` | Секрет подписи ответов сервера: длинная случайная строка (40+ символов). Им же подписываются ответы — кто не знает, «лицензия ок» не подделает |
| `BZW_ADMIN` | Пароль админ-команд (kill, addkey, …) — придумай и запомни |
| `BZW_HOST` | *Не обязателен.* Хост приложения, если имя по умолчанию `benzware-license-server.fly.dev` менялось (например, было занято) |

Без `BZW_SECRET` сборка **намеренно падает** с понятной ошибкой — иначе выдал бы
пользователям бинарь, который не проходит ни одну проверку подписи.

Значения зашиваются в бинарь XOR-обфускацией (`xp::_mk`), открытым текстом в
готовом ELF их нет.

### Сборка

Обычный push в ветку → GitHub Actions сам соберёт `benzware.sh`
(подстановка секретов → ndk-build → CRC-патч). Локально:

```bash
ANDROID_NDK_HOME=... BZW_SECRET=тест ./build.sh   # локально секрет можно любой
NOCRC=1 ./build.sh                                 # без CRC-патча (dev)
```

`build.sh` после `ndk-build` сам вшивает CRC32 в `benzware.bin` (нужен `python3`).
Пропустить: `NOCRC=1 ./build.sh` (тогда самопроверка молча отключится).
В CI ничего менять не надо — в образе GitHub Actions `python3` есть.

### Запуск сервера

```bash
cd server
SECRET='та же строка, что S_SECRET' ADMIN_SECRET='твой пароль админа' node server.js
# слушает 0.0.0.0:8787 (порт меняется PORT=..., тогда же поменяй kPort в license.cpp)
```

### Выдача ключа пользователю

```bash
curl -X POST http://СЕРВЕР:8787/admin/addkey -H 'X-Admin: твой пароль' \
     -H 'Content-Type: application/json' -d '{"days":30,"note":"ник покупателя"}'
# → BZWR-XXXX-XXXX-XXXX   (days:0 = бессрочный)
```

Пользователь кладёт ключ в файл и запускает чит как обычно:

```bash
echo "BZWR-XXXX-XXXX-XXXX" > /sdcard/benzware/.lic
./benzware.sh
```

При первом запуске ключ **автоматически привязывается к устройству** (HWID =
хэш android_id + серийника). На другом устройстве тот же ключ не запустится.

## 2. Управление (админ-команды)

Все команды — `curl -X POST http://СЕРВЕР:8787/admin/<команда> -H 'X-Admin: пароль' -H 'Content-Type: application/json' -d '<json>'`.

| Команда | JSON | Эффект |
|---|---|---|
| **`kill`** | `{"on":true}` | **Глобальный выключатель: ВСЕ бинари останавливаются** на следующем heartbeat (≤3 мин) и не запускаются, пока не вернёшь `{"on":false}` |
| `ban` | `{"key":"BZWR-..."}` | Заблокировать конкретный ключ (разбан: `{"key":"...","banned":false}`) |
| `addkey` | `{"days":30,"note":"ник"}` | Создать ключ |
| `delkey` | `{"key":"..."}` | Удалить ключ совсем |
| `unbind` | `{"key":"..."}` | Сбросить привязку к устройству (смена телефона) |
| `extend` | `{"key":"...","days":30}` | Продлить срок |
| `minbuild` | `{"n":2}` | **Выключить все старые сборки**: бинари с `kBuildId < n` получают отказ «требуется обновление». С каждым релизом поднимай `kBuildId` в `license.cpp` |
| `GET keys` | — | Список ключей (привязка, срок, бан) |
| `GET state` | — | Состояние выключателя и min_build |

То есть «выключать бинарь когда хочу» теперь — это **одна команда `kill`** (сразу все)
или **`ban`** (конкретного пользователя) либо **`minbuild`** (все устаревшие сборки).

Что чувствует пользователь: чит пишет в консоль причину («доступ отключён
разработчиком», «ключ заблокирован»…) и завершается; оверлей закрывается штатно.

### Управление с телефона (без компьютера)

Админ-команды — это обычные HTTP-запросы, с телефона их удобно выполнять
бесплатным приложением **HTTP Request Shortcuts** (Play Market): сохраняешь
запросы как ярлыки на рабочий стол — выключатель чита становится кнопкой на
экране телефона. Примеры настроек (URL подставь свой):

| Ярлык | Метод | URL | Заголовок | Тело |
|---|---|---|---|---|
| 🔴 ВЫКЛЮЧИТЬ всё | POST | `http://APP.fly.dev/admin/kill` | `X-Admin: <BZW_ADMIN>` | `{"on":true}` |
| 🟢 Включить обратно | POST | `http://APP.fly.dev/admin/kill` | `X-Admin: <BZW_ADMIN>` | `{"on":false}` |
| 🔑 Новый ключ 30д | POST | `http://APP.fly.dev/admin/addkey` | `X-Admin: <BZW_ADMIN>` | `{"days":30}` |
| 📋 Список ключей | GET | `http://APP.fly.dev/admin/keys` | `X-Admin: <BZW_ADMIN>` | — |

Тип тела: JSON. Либо то же самое из **Termux** — команды `curl` из таблицы выше
работают как есть.

## 3. Бесплатный сервер: куда поставить

Клиент ходит голым HTTP (подделку закрывает HMAC-подпись — см. раздел 4), поэтому
нужен хост, где работает **обычный HTTP без принудительного редиректа на HTTPS**
и где может жить постоянный процесс Node.js.

### Вариант A — Oracle Cloud Always Free ⭐ рекомендую

Единственный по-настоящему бесплатный **навсегда** VPS: VM.Standard.E2.1.Micro
(или ARM Ampere A1 — до 4 ядер/24 ГБ). Полный root, твой порт, никаких засыпаний.

```bash
# на виртуалке (Ubuntu):
sudo apt update && sudo apt install -y nodejs
mkdir xvc && cd xvc && (закинуть server.js sftp/scp)
SECRET='...' ADMIN_SECRET='...' nohup node server.js > log.txt 2>&1 &
# автостарт: cron `@reboot` или systemd-unit
```

Не забудь открыть порт 8787: **Networking → VCN → Security Lists → Add Ingress
Rule (TCP 8787)** в консоли Oracle + `sudo iptables -I INPUT -p tcp --dport 8787 -j ACCEPT`.

Минусы: при регистрации просит карту (не списывает), регион иногда «out of capacity»
для ARM — бери обычный E2.1.Micro, для этого сервера его за глаза.

### Вариант B — Fly.io ⭐ для работы с телефона

Деплой делается **кнопкой в GitHub Actions** — workflow
`.github/workflows/deploy-server.yml` сам создаёт приложение, volume, секреты и
деплоит. Ничего локально ставить не нужно.

1. Секреты `FLY_API_TOKEN`, `BZW_SECRET`, `BZW_ADMIN` — в Settings → Secrets
   (см. раздел 1).
2. **Actions → «Deploy license server (Fly.io)» → Run workflow**. Поле
   `app_name` оставь по умолчанию, если оно не занято; если занято — впиши своё
   (тогда добавь и секрет `BZW_HOST` = `твоё-имя.fly.dev`, чтобы бинарь знал адрес).
3. Зелёная галочка → сервер живёт на `http://<app>.fly.dev`. Проверка:
   `curl http://<app>.fly.dev/api/ping` (или просто открой в браузере — должен
   вернуть JSON с `"ok":true`).

Машинка shared-cpu-1x/256 МБ + 1 ГБ volume укладывается в бесплатный лимит
Pay As You Go (худший случай — около $2/мес; карту при регистрации fly может
попросить — это нормально). Регион по умолчанию `ams` — до тебя и до
RU-пользователей пинг близкий.

> Альтернатива без GitHub — flyctl работает и в **Termux** на телефоне:
> `pkg install tur-repo && pkg install flyctl`, дальше `fly auth login` и те же
> команды из `server/fly.toml`. Но кнопка в Actions удобнее.

### Вариант C — Render (бесплатный план, с оговоркой)

Render force-HTTPS не делает, Node-сервис поднимется сразу. **Но** бесплатный план
засыпает после ~15 минут без запросов и просыпается ~30–60 сек — heartbeat в это
время получает таймаут (клиент это переживёт за счёт grace, но старт «на холодную»
будет долгим). Лечится бесплатным же UptimeRobot: пинг `GET /api/ping` каждые 5 минут —
сервис не засыпает. db.json на бесплатном плане эфемерен (пересоздаётся при
рестартах) — ключи пересоздавать или добавить платный диск.

### Вариант D — бесплатный VPS у друга / свой ПК / Termux

`server.js` неприхотлив: любой Linux c белым или проброшенным портом. На своём ПК:
проброс порта на роутере + любой DDNS. В Termux на старом телефоне —
`pkg install nodejs && node server.js`.

> **Cloudflare Workers / Vercel** — отличные бесплатные serverless-площадки, но их
> бесплатные домены (`workers.dev`, `vercel.app`) **только HTTPS**: принудительный
> редирект 301 сломает наш HTTP-клиент. Подходят, если купишь домен (~200–700 ₽/год)
> и повесишь на него Worker, или когда прикрутишь TLS к клиенту. Пока рекомендую
> A или B — бесплатно и работает из коробки.

## 4. Как это защищает (слои)

1. **Лицензия + HWID.** Без валидного ключа бинарь не стартует; ключ привязан к
   устройству — «скинул другу» не работает.
2. **Kill-switch серверный.** Решение «умереть» принимает сервер, а не код в
   бинаре: подписанный ответ `{"ok":false,"reason":"killed"}` получает каждый
   клиент раз в ≤3 минуты (настройка `kHeartbeatSec`).
3. **HMAC-SHA256 подпись ответов.** Подделать ответ сервера (DNS-spoof, поднять
   свой «сервер», пропатчить ответ в сети) без `SECRET` нельзя — неподписанный
   ответ клиент считает «нет сети», а не «отмена лицензии».
4. **Анти-replay.** Серверное время в ответе монотонно растёт (клиент хранит
   последний `ts` в `.lst` под HMAC) — записанный старый «ok» не переиграть.
   Локальные часы переводить бессмысленно: расчёты идут от серверного времени +
   монотонных часов.
5. **Grace с лимитом.** Если сервер лёг: разрешены офлайн-старты из кэша — не
   дольше 24 ч (`kGraceSec`) и не более 3 подряд (`kMaxGraceBoots`). База этого —
   подписанный `.lst`, подделать его = знать секрет.
6. **Самопроверка целостности.** `patch_crc.py` вшивает CRC32 всего ELF;
   рантайм сверяет `/proc/self/exe` при старте и каждый 10-й heartbeat. Поменял
   байт в бинаре (пропатчил проверку) — CRC не сошёлся — отказ.
7. **Анти-отладка (базовая).** TracerPid, дефолтный порт frida (27042), строки
   `frida`/`gadget` в maps — зациклился вокруг чита с отладчиком — останов.
8. **Обфускация строк** — уже была в проекте (`xp::_mk`); все новые строки
   (адрес сервера, секрет, причины) тоже зашифрованы компайл-тайм XOR.
9. **Уже было в Android.mk:** `-fvisibility=hidden`, `--gc-sections -s`,
   `--strip-all`, без rtti/unwind-таблиц — дизассемблеру и так не сладко.

## 5. Честные пределы (и как поднять планку)

Любую защиту, которая целиком живёт на клиенте, **мотивированный реверсер снимет**:
сейчас достаточно найти и пропатчить `license::Gate` / `Dead()` — CRC-проверку
отключат вместе с ней либо подсунут «правильный» файл. Точки роста по убыванию
эффекта:

1. **Отдавать критичные данные только после verify.** Главный сок бинаря —
   оффсеты (`game_offsets_active.inc` и т.п.). Если бинарь хранит их
   зашифрованными, а ключ расшифровки = производная от `session` (сервер отдаёт
   новую на каждом heartbeat, `license::SessionMask()` уже возвращает) — пропатченный
   бинарь без живого сервера получит мусор вместо оффсетов. Это самая сильная мера
   из доступных: чит физически не может работать без сервера.
2. **Мешать `SessionMask()` в вычисления** адресов/смещений в `game.cpp`/`aim.cpp` —
   один `if (Dead()) break;` в main.cpp перестаёт быть единственной точкой выхода.
3. **Пакер/виртуализация**: собрать тулчейном Obfuscator-LLVM (OLLVM) — `bcf`,
   `fla`, `sub` поверх текущих флагов; или коммерческие VMProtect/Themida (платно).
4. **Нейтральные следы**: `/sdcard/benzware/` и тег logcat `benzware` палят чит при
   беглом взгляде на устройстве — по желанию меняются двумя строками
   (`kCfgDir` в `config.cpp`/`license.cpp`, тег в `license.cpp`).
5. Heartbeat-интервал не делать слишком редким: kill наступает в пределах одного
   интервала (`kHeartbeatSec` = 180 с сейчас).

### Отладка вживую

- `BZKEY=BZWR-... ./benzware.bin` — ключ из переменной окружения (без файла `.lic`).
- `BZHB=5 ./benzware.bin` — heartbeat раз в 5 секунд (проверять kill-switch).
- `NOCRC=1 ./build.sh` — сборка без CRC-патча (самопроверка отключится, в логе
  будет «самопроверка пропущена»).
- Логи клиента: stdout (`[lic] ...`) + logcat по тегу `benzware`.
- Логи сервера: каждая проверка пишет строку (IP, путь, префикс ключа, вердикт).

### Если сервер сдох навсегда

Все клиенты отработают grace (до 24 ч онлайн / 3 офлайн-старта) и остановятся.
Держи бэкап `db.json` (одна команда `scp`), чтобы поднять сервер на новом месте —
достаточно сменить `S_HOST()` и перевыпустить сборку (а `minbuild` поможет
загнать всех на неё).
