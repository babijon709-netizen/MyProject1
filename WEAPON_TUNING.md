# No Recoil / No Spread — данные объектов, без патчей библиотек

## Использование и ограничения

В «Разное → Оружие» — независимые **No Recoil** и **No Spread**, по умолчанию
выключены. Это запись в память игровых объектов, **не read-only и не touch-компенсация**.
Новые функции не записывают инструкции или данные libil2cpp.so, libunity.so и
других библиотек. Они читают метаданные и несколько исходных инструкций для проверки.
Существующая отдельная настройка FPS по-прежнему пишет данные libunity; её
реализация не относится к этому ограничению и не изменена.

Поддерживается локальное оружие точного класса `Oxide.FPHitscan` в двух проверенных
образах. В ожидании подходящего оружия меню сообщает об этом, при ошибке —
показывает отказ применения. В логе: `object-data recoil/spread`, 0 — выключено,
1 — ожидание, 2 — применено, 4 — ошибка памяти/версии/изменённого образа.
Факт включённого переключателя не равен подтверждению успешной записи.

**Перед переходом остановить старый инструмент и полностью перезапустить игру.**
Старая версия могла оставить инструкции изменёнными в живом процессе. Новая
проверяет эти точки чтением и не пытается их «починить» записью в библиотеку.

Отсутствие патча библиотек **не является защитой от бана**. Изменяются клиентские
параметры оружия; серверная валидация остаётся. На Android-устройстве эта реализация
пока не проверена. Визуальное покачивание/анимация выстрела могут сохраняться;
уже накопленная отдача не стирается отдельной записью, а затухает штатно.

## Объектный путь

Свежая статика GameControllerBase → локальный PlayerManager. Дополнительно
проверяются `Mirror.NetworkIdentity.isLocalPlayer` (+0x4A), точные классы и
namespace, native identity Unity-объектов и связь FPObject.player с этим игроком.
Не используются кэш ESP, глобальный поиск оружия или догадки по чужим объектам.

Совпадающие смещения release/beta:

| Источник | Поле |
|---|---|
| PlayerManager | +0x90 FPManager |
| FPManager | +0x58 текущее FPWeaponBase; без fallback на старый объект при переключении |
| FPHitscan | +0xC0 player, +0x130 HitscanWeaponConfig, +0x1F8 calculator, +0x200 WeaponRecoil |
| WeaponRecoil (встроенная структура) | +0 RecoilConfig, +8 HitscanWeaponConfig |
| HitscanWeaponConfig | +0x60 DispersionConfig, +0x68 RecoilConfig |
| calculator: `Ze` / `FJ` | +0x10 DispersionConfig, +0x18 HitscanWeaponConfig, +0x20 cached base dispersion |

Все дублирующие ссылки сверяются. Перед каждой новой записью повторно проверяется
весь путь владельца/оружия/конфигов. ScriptableObject-конфиги могут быть общими
для нескольких экземпляров одного оружия: это **не обещание изоляции параметров
в одном экземпляре**. Урон, темп огня, боезапас и количество снарядов не меняются.

### No Recoil

Обнуляются шесть float полей **живого RecoilConfig**: +0x18/+0x1C MinRecoil,
+0x20/+0x24 MaxRecoil, +0x28/+0x2C MinSideDelta/MaxSideDelta.
Штатный WeaponRecoil читает эти поля при генерации первого и последующих
импульсов; нулевые границы также ограничивают сохранённую горизонтальную часть.
Время отдачи, скорость применения, ADS-множитель и анимационные структуры не трогаются.

### No Spread

Обнуляются minDispersion/maxDispersion в **живом DispersionConfig** (+0x20/+0x24)
и cached base в **экземпляре calculator** (+0x20). Первый путь ограничивает
динамическую составляющую, второй убирает базовую составляющую, в том числе ADS.
Одного изменения HitscanWeaponConfig.BaseDispersion было бы недостаточно:
значение уже скопировано конструктором calculator. Сам HitscanWeaponConfig не записывается.

## Защита записи и восстановление

- Контроллер получает только `read/named/write_heap`, без обычного `write`.
- `write_heap` читает свежую `/proc/<pid>/maps` перед каждым pwrite. Разрешены только
  private RW, non-executable, inode/device/offset=0: безымянные heap mappings и
  ограниченный список heap-меток. File-backed, shared, RX/RWX, ashmem/memfd,
  неизвестные метки и выход за границы mapping отклоняются.
- Безымянные области, непрерывно следующие за файловыми mappings, консервативно
  отклоняются тоже: так не принимается анонимный ELF .bss за heap. На некоторых
  раскладках это может отказать и настоящей куче; обход отказа не предусмотрен.
- Сохраняются исходные значения девяти скаляров. Уже нулевые поля повторно не
  записываются. Изменения игры во время работы становятся новыми исходными значениями.
- При выключении/смене оружия восстанавливаются только собственные нулевые значения
  с живой identity; поверх чужого обновления запись не делается. При временной
  ошибке восстановления состояние сохраняется для повторной попытки.
- Конфиги могут пережить уничтожение оружия, поэтому восстанавливаются по собственной
  class/native identity. Calculator восстанавливается только пока жив прежний
  владелец и сохранились его ссылки. После смены процесса адреса забываются.
- Это внешние чтения/записи, не транзакция с игровым потоком: повторные проверки
  сужают, но не устраняют гонку между чтением и pwrite. При аварийном завершении
  восстановление не гарантировано. Перезапуск игры возвращает штатные объекты.

Build ID release: `d85e63cd8dcbd481695012ef2e284f0eeb9ef307`.
Build ID beta: `e10795349bd7c2cdc7d8527597c64395a4efed79`.
Неизвестные версии отклоняются. Старые точки recoil/spread/loot сверяются с
оригинальными словами без записи. Поиск/подбор инструкций не выполняется.

## Профили

32-байтовый VMW1 v2: биты 5/6 — новые объектные функции, бит 4 выведен из использования.
При импорте VMW1 v1 прежние биты 4/5/6 игнорируются: старый профиль не включает
новую реализацию без явного выбора. FOV, руки и FPS сохраняются. Сброс положения
рук/FOV не отключает независимые оружейные настройки.

## Проверки

```sh
sh tools/weapons/run.sh
sh tools/viewmodel/run.sh
sh tools/hostcheck/run.sh
python3 tools/lang/check.py
# Необязательно: нужны unicorn и два оригинальных ARM64-образа, не включены в Git.
python3 tools/weapons/check_native.py release/libil2cpp.so beta/libil2cpp.so
```

Проверены оба layout при -O0 и -O3 -ffast-math: независимые флаги, отсутствие
повторных записей, снятие pointer tags, неверная версия/старые патчи/владелец,
повторная валидация перед записью, смерть/переключение/перепривязка, retry,
ошибки чтения/записи, NaN/Infinity, исходные значения и смена внешним writer.
Стенд карт проверяет RX, файлы, анонимный .bss, границы и переполнение адресов.
ARM64-стенд выполняет **оригинальные** расчёты recoil/dynamic spread/base spread
на обеих библиотеках с изменением только входных heap-полей: ненулевой контроль,
первый/следующий выстрел, разные random inputs, движение, стрельба и ADS.
Это не тест реальной привязки объектов на телефоне и не тест античита.

На устройстве нужно отдельно проверить оба переключателя, hip/ADS, смену оружия
и возврат к предыдущему, смерть/респавн, выключение/выход, профили v1/v2 и оба
варианта игры. Другие функции на время проверки выключить. Проверка должна
проводиться только там, где такие изменения разрешены.

Быстрый подбор без библиотечных патчей пока не реализован: [FAST_LOOT.md](FAST_LOOT.md).
