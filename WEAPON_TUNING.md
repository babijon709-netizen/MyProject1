# No Recoil / No Spread

## Интерфейс и поведение

Два независимых тумблера в **«Разное → Оружие»**:

- **No Recoil** — при очередном накоплении отдачи записывает нулевой `Vector2` вместо нового горизонтального/вертикального смещения `FPHitscan`.
- **No Spread** — обнуляет результаты обоих расчётов разброса: динамического (движение/стрельба, включая ADS и ограничение min/max) и базового оружейного (включая множитель ADS). Изменяются расчёты, используемые направлением выстрела, а не только размером перекрестия.

По умолчанию выключены. Сохраняются в профиле. У каждого тумблера подключена собственная кадровая анимация. Изменение сразу вызывает контроллер; при ошибке выдаётся тост. Последующие изменения статуса записываются в лог `weapons:`. Периодическая проверка — каждые 250 мс, без повторных записей уже установленных инструкций.

Не зависят от включения аима/ESP/автофарма. «Сброс» FOV/рук и сброс FPS их не выключают. Выключение одного не меняет второй или быстрый подбор. Смена оружия не требует повторного включения: точки находятся в общем коде `FPHitscan`, а не в сохранённом адресе экземпляра оружия.

### Границы

Подтверждён путь **клиентского `FPHitscan`**. Это не обещание поддержки всех других классов оружия, луков, гранат или серверных NPC. Анимации выстрела/качание модели не отключаются: это не No Sway и не отключение аниматора. Уже начатое до включения возвращение камеры от старой отдачи может завершаться штатно.

Количество снарядов за выстрел, расход патронов, темп стрельбы, урон, дальность, перезарядка и сетевые проверки не меняются. Для оружия с несколькими снарядами базовое угловое рассеивание клиента также обнуляется, но число снарядов остаётся прежним.

**Сервер самостоятельно подтверждает попадания.** Локально вычисленное направление не гарантирует, что сервер примет его без собственного расчёта разброса/проверок. На реальном Android-устройстве новая реализация пока не проверена. Не заявляются гарантированные серверные попадания или отсутствие ограничений со стороны игры.

### Отдача

В `FixedUpdate` вычисляется `WeaponRecoil`, применяются множители ADS/модификаций оружия, увеличивается счётчик выстрелов, новая поправка прибавляется к текущему Vector2. Меняется **только финальная запись**:

```asm
STR D0, [X9]     // 0xFD000120 — исходные две float-компоненты
STR XZR, [X9]    // 0xF900013F — две нулевые компоненты, та же ширина записи
```

X9 формируется из текущего `FPHitscan` и соответствующего смещения Vector2. Счётчик выстрелов и остальные действия `FixedUpdate` продолжают выполняться. Сам `FixedUpdate`, генератор случайных чисел или целый метод стрельбы не отключаются.

### Разброс

Оба калькулятора вызываются непосредственно при построении направления выстрела, а также при расчёте отображаемого разброса. Например, в релизе — вызовы `0x6605848 / 0x660599C` в `FPHitscan.sPR`; в бете — `0x656489C / 0x65649F0` в `FPHitscan.umS`.

Динамический разброс зависит от текущей стрельбы, движения, mobility, ADS и min/max. Обнулять только базовое значение недостаточно. В первом калькуляторе заменяется финальный `FCSEL S0,S2,S1,MI` **после clamp**, во втором — финальный `FMUL S0,S0,S1` **после ADS**. Оба заменяются на `FMOV S0,WZR` (`0x1E2703E0`). Возвращается точный `+0.0f`.

Каждая замена — одно выровненное 4-байтовое слово ARM64. Нет многоинструкционного переписывания пролога, раннего выхода с неснятым стеком, глобального изменения `Random`, общей float-константы или конфигурационных ScriptableObject. FP16 не нужен.

## Защита версии и жизненный цикл

`jni/src/weapon_tuning_memory.h` содержит отдельный проверяемый контроллер:

- Проверяет архитектуру, структуру GNU note, все 20 байт build ID и по восемь инструкций вокруг каждого места изменения.
- Не сканирует память для угадывания адресов неизвестных версий.
- До включения No Spread проверяет **обе** точки. Если установка одной не удалась, пытается откатить уже изменённые точки этой функции; `Active` при частичном применении не выставляется. Каждая инструкция остаётся самостоятельной допустимой операцией даже во время перехода между состояниями.
- No Recoil и No Spread независимы: ошибка одного не блокирует работу/восстановление другого.
- После каждой записи проверяет прочитанные байты. Неясный результат записи учитывается до подтверждения или восстановления.
- Восстанавливает только собственные инструкции. Не присваивает чужую идентичную замену и не перезаписывает посторонний код.
- При неудачном восстановлении хранит состояние для повторной попытки; остальные принадлежащие контроллеру точки восстанавливает независимо.
- Перед восстановлением заново проверяет образ. Не переносит право на восстановление между разными build ID, PID/эпохами или базами загрузки.
- На штатном выходе/смене сборки выполняется попытка восстановления через существующий `esp_viewmodel_reset`. Ошибка при завершении логируется. При потере процесса старые адреса забываются **без записи**.

Запись использует существующий `/proc/<pid>/mem`. На стандартном Linux/Android ARM64 обслуживание кеша исполняемой страницы выполняется kernel `copy_to_user_page`; локальный `__clear_cache` на чужом виртуальном адресе не вызывается. Отказы доступа не обходятся альтернативным механизмом.

После принудительного убийства оверлея восстановление не гарантируется. Нужно перезапустить игру, прежде чем запускать другой экземпляр оверлея: чужие оставшиеся патчи новый экземпляр намеренно не принимает за свои.

## Профили

Используются биты 5 (`32`, No Recoil) и 6 (`64`, No Spread) flags существующего расширения VMW1 v1, размер по-прежнему 32 байта. Известная маска — `127`. Все прежние профили загружаются с двумя новыми функциями выключенными. Неизвестный/обрезанный trailer даёт выключенные значения, а не оставшееся состояние прошлого профиля. Старые версии оверлея не знают новые биты и могут отклонить расширение нового профиля; обратное чтение новым оверлеем проверено.

## Проверки

```sh
sh tools/weapons/run.sh
sh tools/viewmodel/run.sh
sh tools/fast_loot/run.sh
sh tools/lang/run.sh
sh tools/hostcheck/run.sh
python3 tools/weapons/check_native.py release/libil2cpp.so beta/libil2cpp.so

# Дополнительно: исполнение реального ARM64-кода в Unicorn.
python3 -m pip install --target .tools/python unicorn
PYTHONPATH=.tools/python python3 tools/weapons/check_native.py --emulate \
    release/libil2cpp.so beta/libil2cpp.so
```

В `build.sh` стенд оружия включён перед NDK-сборкой. Host-тесты проходят с `-O0` и `-O3 -ffast-math`: все сочетания переключателей, отпечатки, чужие патчи, частичная ошибка установки, rollback, ошибки чтения/write/readback, повтор восстановления, смена сессии и образа. Тест профиля проверяет новые флаги и независимость сброса FOV/рук. GUI-проверка сверяет bool каждого тумблера с его кадровой анимацией.

Отдельный дочерний процесс с RX-страницами проверяет реальное применение/восстановление через `/proc/pid/mem`. Нативный стенд сверяет оба исходных ELF и вызовы калькуляторов из стрельбы/прицела. Опциональная эмуляция исполняет реальные функции разброса (включая настоящий вспомогательный mobility-калькулятор беты) и участок накопления отдачи: проверяет обе оси, первый/последующие выстрелы, ADS/обычный режим, движение, min/max, сохранение стека и счётчика выстрелов, оригинальное и изменённое поведение.

Эти проверки не заменяют Android/сетевой тест. На телефоне проверить по отдельности и вместе: стрельбу одиночными и очередью, ADS/от бедра, движение, смену оружия, отключение во время игры, загрузку старого/нового профиля и нормальный выход. Подтверждённый сервером урон проверять отдельно от локальных следов попаданий.
