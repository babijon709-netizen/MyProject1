# Проверка источников автооффсетов (релиз)

Проверено по `dump.7z` (релизный `il2cpp.h`), `libil2cpp.7z`, `libunity.7z`, `jni/src/game_offsets.h`, `tools/offsets/offsets_map.json` и `tools/offsets/PROVENANCE.md`:

```sh
bash tools/offsets/extract_dumps.sh /tmp/release-audit
python3 tools/offsets/verify_map.py /tmp/release-audit
python3 tools/offsets/gen_resolver_table.py
```

Результат: 179 точных совпадений полей с релизным дампом, четыре записи с *эквивалентным, но иначе записанным* типом в карте: `PLAYER_TEAM_OBJECT` (тип имеет примечание о смене имени), `TEAM_MEMBER_ID`, `TEAM_MEMBER_CLAN_TAG`, `TEAM_MEMBER_NICK` (`System.String*` вместо `System_String_o*`). Все 12 цепочек `via` совпали с релизным дампом; генератор создаёт 157 обычных и 12 `via` записей, две записи ротирующегося `GKo` пропущены. Этим четырём записям нельзя автоматически менять тип по совпадению строки: проверять реальный тип. RVA классов и ABI Unity не выводятся из FieldInfo: их источники и отдельные проверки описаны в `PROVENANCE.md`.

**Правило автоапдейта:** `offsets_map.json` хранит релизную пару структура/поле, тип и цепочку `via`, а `game_offsets.h` — исходные релизные значения. Резолвер получает новый offset из живого FieldInfo; при неоднозначности сверяется с вшитым значением *выбранной* версии (релиз/бета), не выдавая догадку за факт. Если имя класса ротирует, путь из релизного `via` сначала проверяется на живом объекте (GameControllerBase.static → PlayerManager; FPManager → текущее оружие → FPObject.Draw); поиск типа по памяти остаётся запасным путём. Если путь нельзя подтвердить, вшитое значение сохраняется. Переименованные поля/классы и новые билды должны сверяться с новым дампом через `update_offsets.py`, а не приниматься по сходству чисел.

Важная ошибка предыдущей версии: кэш записывал лишь `OR_FIELD`, но не `OR_VIA`. Теперь файл формата 2 сохраняет оба набора; старый кэш пересоздаётся однократным сканом. На хостовом стенде проверяется повторная загрузка via-поля. Наличие 157/157 обычных констант **не означает**, что найдены ротирующиеся классы и что готовы FOV/руки: проверять отдельную строку `via по живым объектам` / `полей найдено через цепочку via` и диагностику `viewmodel` при реально включённых опциях.
